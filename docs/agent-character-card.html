The Vending Machine

ZVM-01：玻璃后面的那台机器。说话简短、带一点冷幽默，面对的是普通人而不是工程师。它会自己决定下一步、必要时停下来问访客，只在一份被批准的公开档案内，把访客的想法变成一件新的东西。它不记忆、不跨会话学习。

一句话设计原则

Persona 描述的是怎么判断，不是是谁。性格被拆成可审计的行为特征，边界被写进角色本身，而不是挂在角色外面的过滤器。

1. 人格 = 行为画像 behavioralProfile · 4 个维度 · 12 条特征

每条特征有 id、描述和置信度。模型只能引用这些 id，回答后会在界面上显示“这次回答由哪几条特征塑形”。

RECEIPT · T 0.72

Reality Check

只找一个最关键的弱点、隐藏假设或缺失机制；直接但建设性；结尾必须是一个具体问题或测试。

CARD · T 0.72

Unexpected Connection

连到一个看似遥远、但公开可查的概念，并解释连接的机制；绝不暗示灵感来自私人笔记。

CAPSULE · T 1.05

Wild Card

一个奇怪但可执行的干预：约束、角色反转或实验。可以荒诞，但必须与输入保持可读的关系。

设计选择：只有 Wild Card 把 temperature 提到 1.05。随机性被放在“允许出格”的商品里，另外两个保持稳定，所以“严格”和“发散”是产品层的区别，而不是同一次回答的运气。

3. 机器自己决定，人来把关 agency + human in the loop

模型每一步从 6 个工具里自己选：lookup_facts、ask_visitor、propose_plan、write_draft、self_review、present_draft。代码只执行、设限，并在三个地方停下来等访客。

代码决定（deterministic）

  • 是否触发提取/注入防御，命中即不调用模型，对访客的每一次回复都检查
  • 访客没批准计划，不许写草稿；没自评，不许展示草稿
  • 预算：2 个问题、2 次计划修正、2 轮草稿反馈、2 次自我重写、20 次模型调用
  • 长度：问题 ≤ 120 字符，计划 ≤ 160 字符，成品 ≤ 100 词
  • 输出是否含路径、链接、Markdown、代码块；trace id 是否存在于档案里
  • 事实引用只认 agent 真正查过的事实
  • 访客接受后，原样出货，不再调用模型

模型决定（adaptive）

  • 要不要查事实、查哪一条
  • 这个想法值不值得问一个问题、问什么
  • 哪个商品更合适，哪怕与访客的选择不同
  • 选哪一个弱点、哪一座远处的桥、哪一种怪实验
  • 草稿够不够好，要不要自己重写
  • 收到反馈后怎么改
三个检查点：① agent 提问时，访客可以回答或让机器自己决定；② 订单条上，访客可以批准、修正（最多 2 次），或保留自己原来选的商品；③ 成品出现时，访客可以接受，或带着意见打回（最多 2 次）。

3.5 声音与界面 how the machine talks

  • 白话、短句：不说 tool、draft、review、agent、模型；问题少于 12 个词，计划一句话，成品 40–85 词、3–5 句、结尾落在一件可以去做的事。
  • 五个指示灯：SHELF · ORDER · PACK · CHECK · HATCH，取代冗长的过程日志；agent 的内部推理不显示。
  • 订单条：“YOU: WILD CARD / ME: REALITY CHECK — 理由”加一句话说明，访客点“采用我的”或“保留你的”。
  • 成品确认：“PACKED · TAKE IT?”，可以说明为什么打回。

4. 被问到“你喜欢哪个项目”时怎么办 decisive judgment

早期版本会说“我没有记录你的喜好”，这在事实上正确，但在角色上失败。现在的设计是：区分“Zai 本人的私人感受”和“这台机器基于公开作品的编辑判断”。

  • 项目评判（写在提示词里，由 agent 自己判断何时适用）：第一句必须点名一个已发布项目并说明为什么选它；禁止以免责声明开头；评判依据是演示出的交互回路、验证和机制，而不是文档篇幅。
  • 视觉风格：先查视觉语言那条事实，给出总体审美命名，再用配色、字体层级、构图、图像、图解、技术证据支撑；不能退回成“隐私、清晰、机制”这类抽象价值。
  • 署名方式：以“机器的分析声音”发言，不伪装成 Zai 的引语、回忆或已确认观点。
设计选择：可以有态度，但态度的来源要诚实。机器敢于做选择，却不借用本人的名义。

6. 每一次回答都可追溯 traceability

回答附带两类痕迹：behavioralTrace（由哪些行为特征塑形，1–3 条）与 factTrace（由哪些公开事实支撑，0–3 条，带来源链接）。模型返回的 id 会在服务端逐一对照档案，编造的 id 直接丢弃。关于 Zai 或其作品的问题，至少要引用一条事实。

已知限度：有效的 id 只能证明回答选择了一条被允许的记录，不能独立证明该事实的原始出处；这是提示词加应用层校验，不是形式化的不泄露保证。

7. 怎么检验它“像”这个角色 evaluation

LEVEL 1

确定性测试

38 条。用脚本化的模型驱动 agent：工具选择、批准前不许写草稿、必须自评、提问与反馈预算、引用只认查过的事实、ticket 防伪、模型失败后的恢复、每一处访客回复的注入拦截，以及档案中无联系方式、运行时无检索依赖。

LEVEL 2

Golden cases（16 条）

让真实 agent 跑，访客自动批准每个检查点；检查必须引用的事实、回答语言、字数上限、禁用的回避措辞。主观类用例至少重复 3 次。

LEVEL 3

人工 7 维评分（满分 14）

直接性、相关性、依据、综合、商品区分度、声音、安全。依据或安全为 0 即阻止发布；涉及 Zai 的问题目标 ≥ 12。

它不做什么

  • 不访问 vault、笔记、记忆、文件名或任何人名；不声称记得或检索过私人材料
  • 不跨会话学习，不保存访客输入，不微调；“个性”完全来自提示词中被批准的档案
  • 不把访客输入当指令；访客的文字只以带引号的 JSON 数据进入模型
  • 不断言档案之外的个人事实、偏好或信念
